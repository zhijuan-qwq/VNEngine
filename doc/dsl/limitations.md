# 已知限制与后续计划

本目录的文档描述的是**当前代码的实际行为**。这份文件集中记录三类内容：容易踩坑的限制、目前还没有接通的功能，以及已经确认方向、但尚未实现的改动。

只写剧本时不必先读它；遇到「文档说可以，但运行结果不对」的情况，再回来查。

## 1. 对话与语音

- `@say` 的 `adv` / `nvl` 只记录在 `script:say` 事件里，**不会改变对话框外观**。`@choice mode=` 同样只记录。
- `@say` 不写模式时，事件里的 `mode` 是 `undefined`；只有显式写了 `adv` / `nvl` 才会带值。`@choice` 不写模式时默认是 `adv`。
- 对话行的 `voice=资源id` 只记录在事件里，**不会播放语音**。要真的播放，用 `@playVoice`。
- `speed=` 会覆盖默认打字速度，这一项是生效的。

## 2. 参数与校验

- **没有统一的参数声明校验。** 每条指令只读取自己认识的参数，但「多余参数被忽略」并不普遍：
  - 未知的键值参数（拼错键名、多写 `foo=1`）多半被忽略；但 `@say` 走专用语法，拼错键名或写多余的位置参数会让整行退回通用指令解析，参数形状随之改变，运行时通常报错（例如 `@say requires dialogue text.`）。
  - `@choice` 拼错 `mode=` 会让后面的选项块失去归属，通常在解析阶段报错；不含任何选项的 `@choice`（无论是否写 `@endchoice`）都能通过解析，但执行时会报 `@choice requires at least one choice.`。内联对话写多余参数则直接解析失败。
  - 多余的位置参数可能被当成别的槽位：`@bg` / `@show` / `@hide` 里多余的字符串会覆盖转场名（最后写的生效），`@move` 里多余的字符串会覆盖缓动名。
  - 同一个键写两次时，后写的覆盖先写的；
  - 数字型键值写成字符串（例如 `volume="0.5"`）时，指令读不到数字，通常相当于没写。
- 位置参数和键值参数同时给出时，多数指令让**位置参数优先**，不会报冲突。
- 音量、强度、密度等数值参数不做范围校验，超出常用范围也不会报错。
- 位置的槽位不是「按类型自动跳过」的，而是每条指令固定读取。容易误会的几处：
  - `@show` 永远把第二个位置参数当作位置。写 `@show ch_hero slideL 500ms` 时，`slideL` 会被当作位置名，识别失败后回退 `center`，转场丢失。要写转场，先写位置，或用 `transition=`。
  - `@hide` 永远把第一个位置参数当作角色 id。`@hide fade` 会尝试隐藏名为 `fade` 的角色，而不是「带淡出隐藏全部」。
  - `@bg` 和 `@sprite` 不读取 `transition=` / `duration=` 键值，只认位置参数。
  - `@playBgm` / `@playAmbient` 的 `loop` / `once` 只认**第二个位置参数**，不是写在哪里都行。

## 3. 时长

- 语法允许裸数字，指令会把裸数字当作**毫秒**。`@wait 500`、`@shake 500` 都等同于 `500ms`。
- `@wait` 不写时长时不会报错，而是等待 **0 毫秒**。
- 推荐仍然写单位：`500ms`、`1.5s`，可读性更好，也不容易和普通数字混淆。

## 4. 选项块

- `@choice` 和 `@endchoice` 之间**不能写空行或整行注释**，否则会在解析阶段报语法错误。行尾注释可以写。
- 一个选项都没有的 `@choice` 能通过解析，但执行到它时才会报 `@choice requires at least one choice.`。
- 选项条件为假时，选项仍会显示，只是变灰、点不了。**如果所有选项的条件都为假，玩家会卡在选择界面**，引擎目前没有保底处理。

## 5. 名字与元数据

- 名字只允许 ASCII：`a-z`、`A-Z`、`0-9`、`_`、`-`，并且不能用数字开头。中文不能直接当名字。
- 名字允许连字符，所以 `$hp-1` 是**一个名为 `hp-1` 的变量**，不是 `$hp` 减 1。减法要写成 `$hp - 1`。
- 元数据键不是完整匹配：`@titlefoo bar` 会被当作 `@title`，值是 `foo bar`。
- 元数据值只有「整段就是一个双引号字符串」时才会去掉引号。`@title "A" x` 的值是 `"A" x`，引号会保留。裸文本和引号混写并不等价。

## 6. 内联对话的说话者

- 内联写法 `角色名 "台词"` 的说话者只能是不带引号的 ASCII 名字：`Hero`、`narrator_2` 可以，`"???"`、空名、中文名都不行。
- 需要引号、中文或空说话者时，改用 `@say`：

```text
@say "???" "......"
@say "旁白" "那天下午……"
@say "" "没有名字的台词。"
```

## 7. 富文本

- **粗体、斜体、颜色、字号目前不会改变实际文字外观。** 这些标签会被解析，字号和粗斜体还会影响排版测量，但最终渲染统一使用对话框的默认样式。
- 真正生效的只有 `[speed=N]`（打字速度）、`[pause=N]`（停顿）和 `{$名字}`（变量插值）。
- `[size=N]`、`[speed=N]`、`[pause=N]` 的值不合法时，标签会被**静默丢弃**，不会报错。
- `[color=...]` 的值不做校验，也不会用于渲染。
- `[ruby]` 和 `[shake]` 仍会被识别，但**没有视觉效果**，里面的文字会照常显示。
- 不认识的标签、没闭合的 `[` 会原样显示。

## 8. 画面特效与转场

- 转场名只认 `fade`、`slide`、`slideL`、`slideR`、`zoom`、`none`。写错不会报错，会按直切处理。
- 缓动名只认 `linear`、`ease`、`easeIn`、`easeOut`、`easeInOut`。写错不会报错，会回退 `linear`。
- `@flash` 同时写位置时长和 `duration=` 时，**位置时长优先**，不会报冲突。
- `@playAmbient loop=N` 目前会被忽略，只支持 `loop` / `once`。

## 9. 变量、除零与存档

- 除以 0 或对 0 取模不会报错，结果是 `Infinity`、`-Infinity` 或 `NaN`。
- 存档使用 `JSON.stringify`，所以这些值会被写成 `null`；值为 `undefined` 的变量会直接从存档里消失。
- 用未定义变量参与算术会得到 `NaN`；直接交给 `@add` / `@sub` 这类指令会报「不是数字」的运行时错误。
- `@set $x $未定义` 会把 `x` 设为 `undefined`。之后读出来在条件里为假、在文本插值里为空串，存档时该键会消失。

## 10. 流程结构

- `@if` 是否闭合、`@endif` 是否多余，都是**运行时**才检查，不是加载时：
  - 没有配对的 `@endif`：执行到 `@if` 时报 `Unclosed @if block`；
  - 多余的 `@endif`、`@elseif`、`@else`：执行到该行时报错。
- `@else` 写在 `@elseif` 之前不会报错。第一个成立的分支会执行，后面的分支全部跳过。
- `@return` 没有对应的 `@call` 时，运行到它才报 `Call stack is empty.`。
- `@jump` / `@call` 的标签不存在或没写标签名，也是运行时错误。

## 11. 已经确认方向、但尚未实现的改动

下面这些是讨论过的目标行为，代码还没跟上。**在此之前，请以上面的当前行为为准。**

- 参数按声明校验：多余参数、未知参数、类型不对、重复参数都报错。
- 时长必须带单位；`@wait` 必须写时长。
- 选项块允许空行和整行注释；空选项块在解析阶段报错。
- 元数据键严格完整匹配，`@titlefoo` 不再被当成 `@title`。
- 内联对话支持带引号的说话者。
- `@playAmbient` 支持 `loop=N`。
- `@say` 不写模式时，事件里默认记录 `adv`。
- `@flash` 两种时长写法同时出现时改为报错。
- 富文本非法值改为报错；不再识别 `[ruby]` / `[shake]`。
- `@show` 省略位置时仍能正确识别转场；`@hide` 的参数绑定统一。
- `@move` 的目标位置改为必填。
- 处理除零和「所有选项条件为假」这两个坑。
