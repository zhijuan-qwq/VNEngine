### BUG-001 打字机推进速度慢约 1000 倍（dt 单位不一致）

- **日期**：2026-10-24
- **现象**：游戏启动后对话正文几乎不逐字显示（数十秒才走 1 个字符），且打字机长期处于 busy 状态；页内探针显示 46 帧 update 仅推进 1 个字符。
- **根因**：`UIManager.update(dt)` 的 dt 存在两路来源、两种单位——内部 RAF 回退路径传**毫秒**（`time - lastTime`），而引擎 `Updater`（`autoTick: false` 时驱动 UI 的实际路径）按引擎约定传**秒**。`DialogueBox.update`/`TypewriterState.update` 的契约是毫秒，Updater 路径下打字机速度被缩小 1000 倍。单测各自独立（DialogueBox/UIManager spec 以毫秒调用），集成路径无覆盖，故未暴露。
- **解决方式**：`UIManager.update` 统一为引擎约定的秒（内部 `dialogueBox.update(dt * 1000)` 转毫秒），内部 RAF 同步改为秒并保留 100ms 钳制；`UIManager.spec` 中 `update(16)` 相应改为 `update(0.016)`。
- **状态**：已修复（UI 相关 42 个测试通过，浏览器实测打字机正常逐字显示）。

### BUG-002 结局段落之间缺少截断，真结局放完会顺流进其他结局

- **日期**：2026-10-24
- **现象**：终章三选一选「留下来」（结局 A）并推进到结尾后，剧本没有终止，而是继续播放结局 B（契约线）的台词（页内探针在 pc 1064 观察到「凉。契约的刻印，很凉。」）。
- **根因**：四个结局段落在单一脚本中按顺序排布，转换器只在段落入口生成 `@label ending_x`，段落之间没有 `@end` 截断——上一段播完后 pc 顺流进入下一段。`@label` 只是跳转目标，不改变顺序执行。
- **解决方式**：转换器在每个结局段入口前生成 `@end`（进入下一段只能通过选项跳转），脚本末尾保留唯一的收尾 `@end`。
- **状态**：已修复（静态校验通过，浏览器实测结局 A 播完后脚本正常终止）。

### BUG-003 flag 分支 A 臂末尾误跳 B 臂

- **日期**：2026-10-24
- **现象**：若玩家在第二章选择「追问几百年」（flag `heard_age`），第四章的 flag 分支会先播 A 臂文本、再接着播 B 臂文本。
- **根因**：转换器 `flushFlagBranch` 中 A 臂收尾误写为 `@jump fb1_b`（B 臂入口），应为 `@jump fb1_end`（合流点）。
- **解决方式**：修正跳转目标为合流点标签。
- **状态**：已修复（静态校验通过）。

### BUG-004 立绘按原生尺寸渲染，头部溢出屏幕

- **日期**：2026-10-24
- **现象**：星弥立绘登场后只看到躯干到脚，头部整体被裁出画面外（截图确认）；`CharacterRegistry` 从不设置 `view.scale`，立绘以原生分辨率（约 656×1092）渲染，锚点在脚底（y=720），头部超出 720px 逻辑画面约 372px。
- **根因**：背景有「美术按逻辑分辨率制作、不缩放」的约定，立绘没有对应约定——引擎假定立绘素材恰好是逻辑尺寸，而本项目素材是高清原画，两者不匹配。
- **解决方式**：
  - `CharacterRegistry` 新增 `CHARACTER_HEIGHT_RATIO = 0.88` 与 `spriteFitScale(texture, size)`：立绘统一缩放到「显示高度 = 逻辑高 × 0.88」，脚底锚点落位不变；视图创建、交叉淡入换纹理（新纹理按自身尺寸重新适配）、退场均应用。
  - `transitions` 的 zoom 转场契约增加 `scaleTo`（缺省 1，背景与旧用法不受影响）：zoom 起止从「绝对 1」改为「相对目标缩放」，避免入场补间把适配缩放打回原尺寸。
  - 更新 `CharacterRegistry.spec` 的 zoom 断言（0.85×fit → fit）。
- **状态**：已修复（852 个测试通过、lint/build 全绿；浏览器实测立绘全身入画、表情切换后缩放保持正确）。
- **后续调整（2026-10-25）**：按用户反馈改为常规 VN 上半身取景——`CHARACTER_HEIGHT_RATIO` 拆分为 `CHARACTER_SCALE_RATIO = 1.25`（显示高度 > 画面高，下半身探出屏幕/对话框之外）与 `CHARACTER_TOP_MARGIN_RATIO = 0.06`（头位留白）；显式 `{x,y}` 坐标语义保留为精确落点。两个常量即演出调参旋钮。

### BUG-005 选项面板从屏幕左上角开始渲染、按钮全屏宽

- **日期**：2026-10-25
- **现象**：剧情到分支选项时，选项按钮从画面左上角 (0,0) 开始纵向排布，与右上角按钮栏同区域互相遮挡，且按钮横贯整个 1280px 画面宽（截图确认）。
- **根因**：`ChoicePanel` 缺省 `x=0, y=0`、按钮宽度直接取面板宽度（`UIManager` 又把整屏宽度传给面板）；组件没有高度概念，也没有「选项块应在对话框上方区域居中」的布局约定。
- **解决方式**：`ChoicePanelOptions` 增加 `height` 与 `buttonWidth`；`show()` 时选项块水平居中（按钮宽 `min(width×0.72, 640)`）、在对话框（底部约 30%）以上区域垂直居中（贴顶保底 8%）；`UIManager` 组装时传入画面高度。
- **状态**：已修复（新增布局断言测试；浏览器数值探针：按钮 x=320 宽 640，三选项 y=145.6/211.6/277.6，文字宽度 216–288 均在按钮内）。

### BUG-006 读档模式下点击空槽触发一次注定失败的恢复

- **日期**：2026-10-25
- **现象**：打开「读取进度」点击空槽，`SaveManager.restore` 在 localStorage 找不到存档数据，走到 reject 分支，控制台打出 `[VNEngine] load failed`，面板关闭但什么都没发生，用户得到无反馈的失败。
- **根因**：`SaveLoadMenu` 对所有槽位一视同仁地挂点击回调，没有「空槽在读档语义下不可用」的概念（`SaveSlotInfo.timestamp` 已能区分有无存档）。
- **解决方式**：读档模式下空槽卡片置为禁用态（半透明、无 hover、不可点）；存档模式空槽仍可点（写入空槽是合法操作）。新增对应测试（`should disable empty slots in load mode` / `should allow saving into an empty slot in save mode`）。
- **状态**：已修复（浏览器实测：空槽呈暗淡样式，点击无反应；有档槽正常读取）。

### BUG-007 对话历史把富文本标记原样显示

- **日期**：2026-10-25
- **现象**：打开「对话历史」，心声独白显示为 `[i]那一年的季度复盘，开到了晚上十点半。[/i]`，`[i]` 标记直接可见。
- **根因**：`DialogueHistory` 存的是 `script:say` 的原始文本（含富文本标记），`HistoryView` 直接渲染；只有 `DialogueBox` 走 `parseRichText` 剥标记。
- **解决方式**：`HistoryView.rebuild` 渲染前用同一套 `parseRichText(entry.text).plain` 取纯文本（剧本无 `{$var}` 插值，无需 resolver）。
- **状态**：已修复（浏览器探针：原始文本含 `[i]`，渲染行已剥净；新增 `should strip rich-text markers from the body text` 测试）。

### BUG-008 存档槽摘要文字溢出卡片右缘

- **日期**：2026-10-25
- **现象**：读档面板双列卡片中，30 字摘要（`SaveManager` 的 `LABEL_MAX_LENGTH` 上限）以 18px 渲染约 540px，超出卡片可用宽度（约 441px），文字压过卡片描边。
- **根因**：槽位摘要直接取 `info.label` 整段渲染，未按卡片宽度截断；数据层只保证 30 字上限，不保证适配列宽。
- **解决方式**：`SaveLoadMenu` 新增 `clipText`：按卡片可用宽度量测，超宽截断加省略号「…」。
- **状态**：已修复（浏览器探针：长摘要 429px ≤ 可用 441px 且以「…」结尾；新增 `should clip an over-long summary with an ellipsis` 测试）。
